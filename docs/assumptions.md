## 3. 성공한 가설 — 3번 (발표 1페이지)

### 근거 3가지

**① 복지멤버십 — 미달 정책은 화면에 나타나지 않는다**
요건을 입력받지 않고 행정정보로 자동 판정하여, **받을 가능성이 있는 정책만** 표시한다.
→ 전입 3개월 차 시민은 6개월 뒤 받을 수 있는 정책의 **존재조차 모른다.**
→ "해당 없음"이라고 알려주는 것보다 심각하다. 안 보이므로 기다릴 수도, 준비할 수도 없다.

**② 모의계산 — 미달 시 "대상 아님" 창만 뜬다**
- 입력 필드에 전입일·기준일이 없다 → **시간 이동 수단 자체가 없음** (`as_of` 개념 부재)
- 탭이 정책별로 분리 → 사용자가 정책을 이미 알고 골라 들어가야 함
- 미달 시 어느 조건에서 걸렸는지 설명 없음
- 탭 목록에 화성시 정책 없음 → **중앙 정책 전용**

**③ 지자체 상세 페이지에 마감일이 없다**
신청기간이 "상하반기 연 1회"로만 적혀 있다. 실제 공고는 2026.1.19~3.6이었으나 그 정보가 없다.
복지로 스스로 "최종 수정일이 오래된 경우 해당 지자체에 직접 확인이 필요합니다"라고 안내한다. (최종 수정일 2026-07-03)

### 캡처 목록 (발표자료용)

- [ ] 모의계산 "대상 아님" 팝업
- [ ] 모의계산 입력 폼 (전입일·기준일 필드 부재를 보여줌)
- [ ] 복지로 지자체 상세 페이지 (마감일 없음 + 최종 수정일 안내)

## 4. 4번 — 복지멤버십 범위 (차별화 축 재설정)

행정정보 연동 자동 판정. **매칭 정확도로는 이길 수 없다** (마이데이터 접근권 없음).
수집·정확도 경쟁을 포기하고 아래 3축에 집중한다.

| 축 | 복지로 | 우리 | 구현 |
| --- | --- | --- | --- |
| **시간** | 오늘만 | D-day 예고 | `as_of` + 규칙 2 |
| **이유** | "대상 아님" | 어느 조건에서 걸렸는지 | `reasons` / `waiting_for` |
| **가정** | 불가 | What-if | `overrides` |

### 발표 핵심 문장

> 복지로는 **어떤 정책이 있는지** 알려줍니다.
> 저희는 **당신이 언제 신청할 수 있는지** 알려줍니다.

경쟁이 아닌 보완 프레임 — 심사위원이 공무원이므로 국가 시스템을 깎아내리지 않는다.

## 6. 부수 발견 (개발에 영향)

### A — 크롤링 대상 확대 필요
**청년 정책 공고는 시청 본청 고시공고에 없다.** 구청 게시판과 청년지원센터에 분산돼 있다.

| 위치 | 경로 |
| --- | --- |
| 구청 게시판 (만세·동탄 등) | `hscity.go.kr/{구청}/user/bbs/...q_bbsCode=1048` |
| 청년지원센터 HEY | `hey.hscity.go.kr` |
| 본청 일반공고 | `hscity.go.kr/www/gosi/BD_selectGosiList.do` |

→ 본청만 크롤링하면 청년 정책이 통째로 빠진다.

### A — 파싱 프롬프트 규칙 추가
소득 조건은 **"기준중위소득 N%"로 명시된 경우에만** `conditions.income_percentile`.
건강보험료 본인부담금·연소득 절대액 등 다른 지표는 `manual_conditions`로.
(실제 사례: hs-2026-0263은 중위 180% → `conditions` / hs-2026-2673은 건보료 129,141원 → `manual_conditions`)

### A — 서술형 조건은 예외가 아니라 다수
확보한 2건 모두 `manual_conditions`가 6~7개. 8/7 조건 이원화 결정이 없었다면 이 정보가 통째로 사라졌다.

### A — 홈페이지 요약과 공고문이 다를 수 있다
담당부서명이 홈페이지 요약은 "청년청소년과", 공고문 원문은 "청년청소년정책과 청년지원팀". **원문 우선.**

### B — `verify_required` ⊆ `conditions` 키 검사 추가
`conditions`에 없는 키를 `verify_required`가 참조하면 무의미하고 API 정규화 시 혼란.
적재 스크립트에 자동 검사 추가 권장. (실제로 hs-2026-2673 초안에서 발생 → 수정 완료)

### B — 조건이 사실상 비는 정책 처리 확인
상시 접수(`deadline: null`) + 조건 대부분이 서술형인 정책이 존재.
`conditions`가 거의 빈 상태로 판정에 들어갈 때 규칙 엔진이 정상 동작하는지 확인 필요.

### C·D — `eligible`은 수급 확정이 아니다 ⚠️
hs-2026-2673은 **자격요건 충족자 중 건강보험료 낮은 순으로 선정**하는 배점 경쟁 사업이다.
자격이 충족돼도 탈락할 수 있다. **UI에 디스클레이머 문구 필요.**
(예: "신청 자격을 충족합니다. 최종 선정은 심사 결과에 따릅니다.")
