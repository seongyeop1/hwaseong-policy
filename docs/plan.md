# 기획서 — 개인별 맞춤형 정책 지원 분석 플랫폼

> AI 화성 챌린지 주제2 · 4인 팀 · 제출 2026-08-19
> 이 문서의 수치는 전부 `main` 실측이다. 근거 문서는 각 절에 링크했다.

---

## 1. 한 줄로

> 복지로는 **어떤 정책이 있는지** 알려줍니다.
> 저희는 **당신이 언제 신청할 수 있는지** 알려줍니다.

화성시 지원정책을 시민의 프로필로 판정해 **지금 신청 가능 / 서류 확인 필요 / 곧 가능(D-day)** 세 갈래로 보여준다.

---

## 2. 왜 이 문제인가 — 전제를 먼저 깨봤다

기획을 확정하기 전에 **가설 9종을 실증**했다. 결과는 `docs/assumptions.md`.

### 버린 가설 2개

| 가설 | 검증 | 결과 |
|---|---|---|
| 화성시 자체 사업이 복지로에서 누락된다 | 청년 정책 2건 복지로 검색 | ❌ **둘 다 등재돼 있음** |
| 복지로의 신청 안내가 얕다 | 지자체 상세 페이지 확인 | ❌ **자격·서식 파일까지 제공** |

**"국가 시스템에 빈틈이 있다"는 각도는 성립하지 않았다.** 여기서 방향을 틀었다.

### 살아남은 가설 — 시간축

복지로·복지멤버십에서 **조건에 미달하면 정책이 화면에 나타나지 않는다.**

- **복지멤버십** — 받을 가능성이 있는 정책만 표시한다. 전입 3개월 차 시민은 6개월 뒤 받을 수 있는 정책의 **존재조차 모른다**
- **모의계산** — 미달 시 "대상 아님" 창만 뜬다. **입력 필드에 전입일·기준일이 없어 시간 이동 수단 자체가 없다**
- **지자체 상세 페이지** — 신청기간이 "상하반기 연 1회"로만 적혀 있다. 실제 공고는 2026.1.19~3.6이었으나 그 정보가 없다

> "해당 없음"이라고 알려주는 것보다 심각하다. **안 보이므로 기다릴 수도, 준비할 수도 없다.**

---

## 3. 차별화 — 세 개 축

매칭 정확도로는 이길 수 없다(마이데이터 접근권이 없다). 수집·정확도 경쟁을 포기하고 세 축에 집중했다.

| 축 | 기존 서비스 | 우리 | 구현 |
|---|---|---|---|
| **시간** | 오늘만 | **D-day 예고** | `as_of` + 분류 규칙 2 |
| **이유** | "대상 아님" | **어느 조건에서 걸렸는지** | `reasons` / `waiting_for` |
| **가정** | 불가 | **What-if 시뮬레이터** | `overrides` |

**경쟁이 아니라 보완 프레임**이다. 국가 시스템을 깎아내리지 않는다.

## 4. 설계 원칙 — 판정은 코드가, 설명은 AI가

이 프로젝트의 핵심 결정이다.

```
evaluate(profile, policy, as_of) → 순수 함수
  전역 상태 금지 · LLM 호출 금지 · 네트워크 호출 금지
  기준일은 as_of 인자로만 (datetime.now() 금지)
```

**LLM은 요청 경로에 없다.** 따라서 판정은 **재현 가능**하다 — 같은 입력이면 언제 돌려도 같은 결과가 나온다.

다만 **LLM 은 파싱도 한다.** 파싱이 틀리면 판정도 틀리므로, 그쪽은 구조가 아니라
**2인 교차 전수 검수**로 막는다. "환각에 의한 판정 오류가 불가능하다" 고는 말하지 않는다.

AI가 하는 일은 두 가지뿐이다.

| 단계 | 역할 | 위치 |
|---|---|---|
| 배치 파싱 | 정책 공고 원문 → JSON | `scripts/parse.py` (사람이 검수) |
| 판정 후 요약 | 결과 설명 문장 생성 | `apps/api/tools/generate_summaries.py` (배치·사전 생성) |

요약도 **미리 만들어 파일로 커밋**하고 API는 읽기만 한다. 정책이 수정되면 내용 해시가 달라져 **낡은 요약은 자동으로 차단**된다 — 틀린 금액을 안내하느니 "요약 준비 중"을 표시한다.

### 조건이 애매하면 판정하지 않는다

기계로 판정 가능한 값(나이·거주개월·가구유형)만 `conditions` 에 넣고, 서술형 자격요건("무주택자에 한함")은 `manual_conditions` 로 분리한다. **서술형 조건이 하나라도 있으면 그 정책은 '서류 확인 필요'가 최대**다.

> 자격이 없는 분께 "대상입니다"라고 말하지 않기 위해서다.

## 5. 분류 규칙 — 정본은 계약서

`packages/schema/api-contract.md`. 한 (정책, 가구원) 쌍은 세 목록 중 **정확히 한 곳**에만 나타난다.

| # | 조건 | 결과 |
|---|---|---|
| 0 | 마감일이 지남 | 비대상 (응답 제외) |
| 1 | 90일 내 충족 불가 (나이 상한 초과 등) | 비대상 |
| 2 | 시간이 지나면 충족됨 | 충족 예정일 ≤ 마감일이면 **`upcoming`** (D-day 표시) |
| 3 | 기계 판정 통과, 확인 항목만 남음 | **`docs_needed`** |
| 4 | 전부 통과 + 확인 항목 없음 | **`eligible`** |

규칙 2가 이 서비스의 핵심이다. **충족 시점이 마감 이후면 D-day를 보여주지 않는다** — 기다려도 소용없는 정책에 희망을 주지 않기 위해서다.

## 6. 데이터 신뢰성 — 구조가 아니라 사람이 막는다

판정 오류는 구조로 막았다. 그러나 **데이터 오류는 구조로 막을 수 없다.**

### 2인 교차 전수 검수

정책 1건마다 **파싱 담당이 아닌 1인**이 공고 원문과 대조하고, 그 기록을 JSON에 남긴다.

```jsonc
"review": {
  "parsed_by": "A", "reviewed_by": "D", "reviewed_at": "2026-08-16",
  "checklist": { "conditions": true, ..., "conditions_complete": true }
}
```

- `parsed_by == reviewed_by` 면 **CI가 실패**한다
- 체크리스트 ⑦ `conditions_complete` — **공고의 모든 자격요건이 빠짐없이 옮겨졌는가**
- 검수 기록이 없거나 미완이면 **런타임에서도 서빙되지 않는다** (`store.py` 검수 게이트)

### 실제로 무엇을 막았나

`hs-2026-0263`(청년 중개보수·이사비) 검수에서 **신청 제외대상 8건 중 5건이 통째로 누락**된 것을 발견했다. 기초생활수급자·외국인·재외국민·시설 수급자·직계존속 임대인 — 전부 자격요건인데 파싱에서 빠졌다.

**그리고 이 상태는 스키마 검증을 통과한다.** 형식은 완벽했기 때문이다.

> 체크리스트 ⑦이 없었다면 해당자에게 "신청 가능"으로 표시됐을 것이다.
> 구조가 아니라 사람이 잡은 오류다.

## 8. 시연

검증된 페르소나 3종은 `docs/demo-scenarios.md` 에 **실측값**으로 정리돼 있다.

| 페르소나 | 결과 (`eligible` / `docs_needed` / `upcoming`) |
|---|---|
| 청년 전입자 | 1 / 21 / **1 (D-61)** |
| 노인 전입자 | 1 / 11 / **2 (D-13)** |
| 유자녀 가구 | 1 / 16 / **1 (D-74)** |

`as_of` 를 요청에 넣어 **기준일을 고정**할 수 있다. 리허설과 시연의 D-day 숫자가 흔들리지 않고, What-if 시간 이동도 같은 메커니즘을 쓴다.

## 9. 한계 — 알고 있는 것

정직하게 적는다.

| 한계 | 내용 |
|---|---|
| **`eligible` 은 수급 확정이 아니다** | 자격 충족자 중 배점 순으로 선정하는 경쟁 사업이 있다. UI에 디스클레이머를 함께 표시한다 |
| 소득은 입력받지 않는다 | 프로필로 판정할 수 없어 자동으로 '서류 확인 필요'로 분류한다. 정확도를 포기하고 **오판을 피하는** 선택이다 |
| 일수 단위 조건 | "180일 거주"를 `residence_months: 6` 으로 근사한다. D-day에 며칠 오차가 있다 |
| 나이 구간 표기 | 공고가 출생일 구간으로 대상을 지정하면 만 나이로 재현되지 않아 `manual_conditions` 에 병기한다 |
| 커버리지 | 화성시 전체 정책이 아니라 크롤링 대상 게시판의 수집분이다 |

## 10. 로드맵 (베타)

대회 산출물이 아니라 **정식 런칭 단계** 항목이다.

- PostgreSQL(Supabase) 전환 — 현재는 파일 스토어
- 신규 공고 자동 감지 상시화 — 현재는 수동 실행 + `first_seen` 기록
- 알림(전입 N개월 도달 시 D-day 안내)
- 대화형 입력 · 음성 입력
