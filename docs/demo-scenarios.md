# 시연 시나리오 — 페르소나 · as_of 고정값

> 갱신: 2026-08-12 (정책 7건 기준) · 근거: `main` 실측
> 아래 숫자는 전부 실행 결과다. 추정값이 아니다. 재현 방법은 마지막 절.

## ⚠️ 먼저 — 청년 페르소나는 `as_of` 고정이 필수다

정책 7건의 마감일 분포.

| policy_id | 정책 | 마감 |
|---|---|---|
| hs-2026-0263 | 청년 부동산 중개보수·이사비 | 2026-03-06 **(종료)** |
| hs-2026-2673 | 청년 내:일(job)응원금 2차 | **2026-08-14** |
| hs-2026-2594 | 청년 전(월)세 대출이자 | **2026-08-14** |
| hs-2026-0000 | 노인 보청기 | 상시 |
| hs-2026-0001 | 성인용 보행기 | 상시 |
| hs-2026-0002 | 출산지원금 | 상시 |
| hs-2026-0003 | 임신·출산 부모교육 | 상시 |

**청년 정책 3건이 모두 8/14 이전에 마감된다.** 규칙 0(마감 종료 제외)에 의해 8/15부터 응답에서
빠지고, **발표일은 8/20 이라 이미 전부 지난 뒤다.**

```
청년 페르소나 · as_of 2026-08-20 (고정하지 않은 경우)
  → eligible 1 / docs_needed 0 / upcoming 0     ← 청년 정책이 전부 사라짐
```

`eligible` 1건은 상시 접수인 `hs-2026-0003`(부모교육)이라 남은 것이다.
**D-day 도, 서류 확인 목록도 보이지 않는다** — 발표의 핵심인 시간축이 사라진다.

### 대응

1. **페르소나 A 는 `as_of` 를 2026-06-01 로 고정한다.** 계약서가 `as_of` 를 넣어둔 이유가 이것이다
2. **페르소나 B·C 는 고정 없이도 동작한다** (상시 접수 정책 기반) — 라이브 시연의 안전판
3. 근본 해결은 마감이 8/20 이후인 정책 확보 → **#31 · #10 · #24**

## 페르소나 A — 청년 전입자 · **3분류가 모두 채워지는 유일한 조합**

```json
{
  "birth_date": "1999-03-02",
  "region": "화성시 동탄5동",
  "move_in_date": "2026-02-01",
  "lifecycle": ["전입", "청년"],
  "household_type": "1인가구",
  "as_of": "2026-06-01"
}
```

**결과 — `eligible` 1 / `docs_needed` 1 / `upcoming` 1**

| 분류 | 정책 | 내용 |
|---|---|---|
| **eligible** | hs-2026-0003 임신·출산 부모교육 | 기계 조건 통과 + 확인 항목 없음 |
| docs_needed | hs-2026-2594 청년 전월세 대출이자 | 소득·서술형 확인 남음 |
| **upcoming** | hs-2026-2673 청년 내:일응원금 | **D-61 (2026-08-01 충족)** — 거주 6개월 |

**`as_of` 를 2026-06-01 로 고정해야 한다.** 세 칸이 동시에 차는 조합은 현재 이것뿐이다.

### 보여주는 것

- **3분류 대시보드 전체** — 확정 / 서류 확인 / 예정이 한 화면에
- **시간축** — "8월 1일부터 신청할 수 있습니다"
- **`upcoming` 의 `verify`** — 거주 요건이 충족돼도 소득 서류가 남는다는 안내
  ("미리 준비하세요" 문구의 근거 데이터)

## 페르소나 B — 노인 전입자 · 발표일에도 동작

```json
{
  "birth_date": "1955-05-05",
  "region": "화성시 봉담읍",
  "move_in_date": "2025-09-01",
  "lifecycle": ["노후"],
  "household_type": "1인가구",
  "as_of": "2026-08-20"
}
```

**결과 — `eligible` 1 / `docs_needed` 0 / `upcoming` 2**

| 분류 | 정책 | 내용 |
|---|---|---|
| eligible | hs-2026-0003 임신·출산 부모교육 | |
| **upcoming** | hs-2026-0000 노인 보청기 | **D-12 (2026-09-01)** — 거주 12개월 |
| **upcoming** | hs-2026-0001 성인용 보행기 | **D-12 (2026-09-01)** — 거주 12개월 |

전부 상시 접수라 **마감 절벽의 영향을 받지 않는다.** `as_of` 고정 없이 발표 당일에 그대로 돌려도
같은 결과가 나온다 — **라이브 시연의 안전판.**

> `eligible` 에 부모교육이 뜨는 건 이 정책에 나이 제한이 없기 때문이다. 판정은 정확하지만
> 71세 프로필에 "임신·출산 부모교육"이 확정 대상으로 뜨는 그림이 어색하다면, 시연에서
> 이 카드를 언급하지 않거나 페르소나 C 를 쓰는 편이 낫다.

## 페르소나 C — 유자녀가구 · 발표일 기준 가장 자연스러움

```json
{
  "birth_date": "1992-04-10",
  "region": "화성시 향남읍",
  "move_in_date": "2026-05-01",
  "lifecycle": ["출산·육아"],
  "household_type": "유자녀가구",
  "as_of": "2026-08-20"
}
```

**결과 — `eligible` 1 / `docs_needed` 0 / `upcoming` 1**

| 분류 | 정책 | 내용 |
|---|---|---|
| eligible | hs-2026-0003 임신·출산 부모교육 | 생애주기가 맞아떨어진다 |
| **upcoming** | hs-2026-0002 출산지원금 | **D-73 (2026-11-01)** — 거주 6개월 |

`hs-2026-0002` 는 **가구 유형을 `유자녀가구`·`다자녀` 로 제한하는 첫 정책**이다.
따라서 이 페르소나에서만 **`household_type` What-if 가 실제로 결과를 바꾼다**
(가구 유형을 `1인가구` 로 바꾸면 출산지원금이 사라진다).

> `hs-2026-0002` 의 거주 요건은 원문이 **180일**인데 스키마에 일수 단위가 없어
> `residence_months: 6` 으로 근사했다. D-day 에 며칠 오차가 있다 (2026-05-01 전입 기준 약 4일).

## What-if 시뮬레이터에서 실제로 먹히는 노브

계약서 v1.1.2 참조. `overrides` 6종 중 결과를 바꾸는 것은 세 개뿐이다.

| 노브 | 효과 | 시연 예 |
|---|---|---|
| `birth_date` | 나이 조건 | 34세 → 35세로 옮기면 나이 상한 정책이 사라진다 |
| `move_in_date` | 거주개월 · D-day | 전입일을 당기면 `upcoming` → `docs_needed` 로 이동 |
| `household_type` | 가구 제한 정책에만 | 페르소나 C 에서 `1인가구` 로 바꾸면 출산지원금이 빠진다 |
| 최상위 `as_of` | 시간 이동 | `upcoming` → `docs_needed` |

**`members`(자녀 추가) · `region` · `lifecycle` 은 지금 결과를 바꾸지 않는다.**
계약서의 "둘째가 태어나면?" 예시는 가구 판정(8/14~) 이후에야 동작한다 — 버그가 아니다.

## 알려진 표시 한계

- **`eligible` 카드의 `reasons` 가 비어 있다** (#37). `hs-2026-0003` 은 `conditions` 가
  `household: ["제한없음"]` 뿐이라 엔진이 적을 통과 사유가 없다. 판정은 정확하지만
  화면에 이유가 표시되지 않는다 — 발표 3축 중 "이유"에 해당하므로 확인 필요
- **`eligible` 은 수급 확정이 아니다** (#15). UI 라벨이 "확정 대상"으로 되어 있어
  디스클레이머가 필요하다

## 재현 방법

```bash
cd apps/api
pip install -r requirements.txt
python - <<'PY'
from datetime import date
from app.store import load_policies
from app.schemas import Profile
from app.engine.evaluate import evaluate_all

P = load_policies()
prof = Profile(
    birth_date=date(1999, 3, 2), region="화성시 동탄5동",
    move_in_date=date(2026, 2, 1), lifecycle=["전입", "청년"],
    household_type="1인가구",
)
r = evaluate_all(prof, P.values(), date(2026, 6, 1))
for k in ("eligible", "docs_needed", "upcoming"):
    print(k, [i["policy"]["policy_id"] for i in r[k]])
PY
```

API 로 확인하려면 위 JSON 을 그대로 `POST /evaluate` 에 보내면 된다 (`as_of` 포함).
