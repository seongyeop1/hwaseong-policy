규칙 0(마감 종료 제외)에 의해 8/15부터 응답에서 빠지므로, **제출·발표일에는 이미 지난 뒤다.**

```
페르소나 A(청년 전입자) · as_of 2026-08-19 (고정하지 않은 경우)
  → eligible 1 / docs_needed 12 / upcoming 0     ← 이 페르소나만 D-day 가 사라진다
```

**거주개월 기반 D-day 를 쓰는 페르소나 A 에만 해당한다.** 다른 페르소나는 영향이 없다.

### 페르소나별 `as_of` 필요 여부

| 페르소나 | `as_of` 고정 | 이유 |
|---|---|---|
| **D — 나이 경계** ⭐ | **불필요** | 상시 접수 + **나이 하한** 도달로 D-day 가 생긴다 |
| B — 노인 전입자 | 불필요 | 상시 접수 정책 기반 |
| C — 유자녀 가구 | 불필요 | 상시 접수 정책 기반 |
| A — 청년 전입자 | **2026-06-01 필수** | 쓰는 정책 3건이 8/14 이전 마감 |

**시연 영상은 페르소나 D 로 찍는다.** `as_of` 를 건드리지 않으므로 "날짜를 맞춰둔 것 아니냐"는
질문이 원천적으로 없고, D-day 카드도 3장이라 화면이 더 설득력 있다.

페르소나 A 는 **거주개월 기반 D-day 서사**(전입 → N개월 뒤)가 필요할 때만 쓴다.

## 페르소나 A — 청년 전입자 · 거주개월 기반 D-day

```json
{
  "birth_date": "1999-03-02",
  "region": "동탄5·6동",
  "move_in_date": "2026-02-01",
  "lifecycle": ["전입", "청년"],
  "household_type": "1인가구",
  "as_of": "2026-06-01"
}
```

**결과 — `eligible` 1 / `docs_needed` 16 / `upcoming` 1**

| 분류 | 대표 정책 | 내용 |
|---|---|---|
| **eligible** | hs-2026-0003 임신·출산 부모교육 | 기계 조건 통과 + 확인 항목 없음 |
| docs_needed | 16건 (hs-2026-2594 청년 전월세 대출이자 외) | 소득·서술형 확인이 남은 정책들 |
| **upcoming** | hs-2026-2673 청년 내:일응원금 | **D-61 (2026-08-01 충족)** — 거주 6개월 |

**`as_of` 를 2026-06-01 로 고정해야 한다.** `upcoming` 이 채워지는 청년 조합은 현재 이것뿐이다.

### 보여주는 것

- **3분류 대시보드 전체** — 확정 / 서류 확인 / 예정이 한 화면에
- **시간축** — "8월 1일부터 신청할 수 있습니다"
- **`upcoming` 의 `verify`** — 거주 요건이 충족돼도 소득 서류가 남는다는 안내
  ("미리 준비하세요" 문구의 근거 데이터)

## 페르소나 D — 나이 경계 · ⭐ **시연 영상 1순위**

```json
{
  "birth_date": "2007-09-20",
  "region": "동탄5·6동",
  "move_in_date": "2020-01-01",
  "lifecycle": ["청년"],
  "household_type": "1인가구"
}
```

**`as_of` 를 보내지 않는다.** 서버의 오늘 날짜로 판정해도 D-day 가 나온다.

**결과 — `eligible` 1 / `docs_needed` 9 / `upcoming` 3** (as_of 2026-08-19 기준)

| 분류 | 정책 | D-day |
|---|---|---|
| **upcoming** | hs-2026-1276 경기 고립·은둔 청년 지원 | **D-32** (2026-09-20) |
| **upcoming** | hs-2026-1359 사회적가치형 청년 일경험 인턴 | **D-32** |
| **upcoming** | hs-2026-1360 경기청년 일자리 매치업 플러스 | **D-32** |

```
waiting_for : "만 19세 요건 충족까지 (생년월일 2007-09-20 기준)"
```

### 왜 1순위인가

- **`as_of` 를 조작하지 않는다** → "날짜를 맞춰둔 것 아니냐"는 질문이 원천적으로 없다
- **D-day 카드가 3장** — 페르소나 A(1장)보다 화면이 설득력 있다
- 세 정책 모두 **상시 접수**라 마감 절벽의 영향을 받지 않는다. 날짜가 바뀌어도 D-day 숫자만 줄어든다
  (8/17 이면 D-34, 8/19 면 D-32)

> **시연 멘트**
> "만 19세 생일이 32일 남았습니다. 그날부터 이 3개 정책에 신청할 수 있습니다."

**D-day 는 거주개월뿐 아니라 나이 하한 도달로도 생긴다**(분류 규칙 2). 이 페르소나가 그 경로를 쓴다.

### 변형

`birth_date` 를 `2011-10-01`(14세→15세)로 바꾸면 `hs-2026-1263`·`hs-2026-1370`(둘 다 15세 이상)이
D-43 으로 잡힌다. 나이 하한이 다른 정책군을 보여주고 싶을 때 쓴다.

## What-if 시뮬레이터에서 실제로 먹히는 노브

계약서 v1.1.4 참조. `overrides` 6종 중 결과를 바꾸는 것은 세 개 + 조건부 한 개(`members`)다.

| 노브 | 효과 | 시연 예 |
|---|---|---|
| `birth_date` | 나이 조건 | 34세 → 35세로 옮기면 나이 상한 정책이 사라진다 |
| `move_in_date` | 거주개월 · D-day | 전입일을 당기면 `upcoming` → `docs_needed` 로 이동 |
| `household_type` | 가구 제한 정책에만 | 페르소나 C 에서 `1인가구` 로 바꾸면 출산지원금이 빠진다 |
| 최상위 `as_of` | 시간 이동 | `upcoming` → `docs_needed` |

**`members`(자녀 추가)는 프론트에서 동작한다.** `자녀 1명 추가` 토글을 켜면
`overrides.members` 에 본인+자녀를 실어 `/evaluate` 를 다시 부른다 (`analysis/page.tsx`).
페르소나 D 에서 켜면 **`hs-2026-0002` 출산지원금이 들어오고 `hs-2026-1281`(1인가구 전용)이 빠진다** —
건수는 그대로인데 내용이 바뀌므로 "얻는 것과 잃는 것이 같이 계산된다"를 보여줄 수 있다.

> ⚠️ **`for_member: "자녀"` 표시는 지금 데이터로 못 보여준다.**
> `beneficiary: 자녀` 정책이 `hs-2025-0002` 하나였는데 **#83 으로 제거됐다**(2025년 사업).
> 엔진의 가구원 단위 판정은 정상이고 테스트로 고정돼 있다 — 자녀 대상 정책이 들어오면 다시 나타난다.
> 발표에서 물어보면 대본 Q14 로 답한다.

`region` · `lifecycle` 은 판정 조건이 아니라 결과를 바꾸지 않는다.

## 시연 영상 촬영 절차

> 촬영은 발표 당일이 아니라 미리 한다. 아래는 **제출용 배포에서 8컷을 실제로 돌려보며 확인한 것**이다.

### 찍기 전

| ☐ | 준비 | 왜 |
|---|---|---|
| ☐ | **keep-warm 수동 실행 → `/health` 1초 내 응답** | 콜드 스타트가 최대 리스크다. 첫 분석에서 수십 초 멈추면 그 테이크는 버린다 |
| ☐ | 주소가 `hwaseong-policy-five.vercel.app` 인지 | 폐기 배포 3개가 아직 200 을 준다 (#79). 주소만 보고는 구별되지 않는다 |
| ☐ | **깨끗한 브라우저 프로필 또는 시크릿 창** | 확장·북마크·자동완성이 화면에 찍힌다 |
| ☐ | HEY 포스터를 미리 한 번 열어 캐시 | `hs-2026-1276` 포스터가 5.7MB 라 컷 5-1 에서 흰 화면이 몇 초 찍힌다 |
| ☐ | 1920×1080 · 배율 100~110% | 슬라이드에 축소돼 들어가도 글씨가 읽혀야 한다 |
| ☐ | **무음으로 찍기** | 발표는 영상을 틀고 **발표자가 말로 얹는다**(대본 파트 3). 무음이면 재촬영 부담이 크게 준다. 다만 영상이 따로 열람될 수 있으니 **자막은 넣는다** |

### 찍는 중 — 실측으로 확인된 함정

- **폼 단계 전환에 애니메이션이 있다.** 단계를 넘긴 직후 바로 누르면 버튼이 아직 이동 중이라 빗나간다.
  각 단계 후 **0.5~1초 쉬고** 클릭한다.
- **`자녀 1명 추가` 는 행이 아니라 토글 스위치를 눌러야 먹는다.** 라벨 쪽을 누르면 아무 반응이 없다
  (`6개월 뒤로 시간 이동` 은 행 전체가 먹힌다). 카메라 앞에서 두 번 누르는 장면이 안 나오게 미리 손에 익힌다.
- **What-if 토글은 `/evaluate` 재호출이라 응답까지 약 3초.** 컷 6·7 에 각각 3초짜리 정지 화면이 생긴다.
  멘트로 덮거나 편집에서 배속한다.
- **`서류 확인` 9건은 5건까지만 보이고 나머지는 `4건 더 보기` 로 접혀 있다.**
  컷 7 에서 `1인 생활 공작소` 가 빠지는 걸 보여주려면 **미리 펼쳐둔다.**
- **자정을 넘겨 찍지 않는다.** D-day 와 화면 기준일이 한 영상 안에서 바뀐다.

### 날짜에 따라 달라지는 값

| 촬영일 | 3분류 | D-day | 화면에 찍히는 기준일 |
|---|---|---|---|
| 2026-08-18 | 1 / 9 / 3 | **D-33** | `2026-08-18` |
| 2026-08-19 | 1 / 9 / 3 | **D-32** | `2026-08-19` |

기준일은 #92 로 **결과 헤더에 표시된다**(`분석 결과 · 기준일 YYYY-MM-DD`).
시간 이동을 켜면 `+6개월` 값으로 **같이 움직인다** — What-if 가 실제 재판정이라는 증거라 컷 6 에서 짚는다.

## 재현 방법

```bash
cd apps/api
pip install -r requirements.txt
python - <<'PY'
from datetime import date
from app.store import load_policies
from app.schemas import Profile
from app.engine.evaluate import evaluate_all

P = load_policies()
prof = Profile(
    birth_date=date(1999, 3, 2), region="동탄5·6동",
    move_in_date=date(2026, 2, 1), lifecycle=["전입", "청년"],
    household_type="1인가구",
)
r = evaluate_all(prof, P.values(), date(2026, 6, 1))
for k in ("eligible", "docs_needed", "upcoming"):
    print(k, [i["policy"]["policy_id"] for i in r[k]])
PY
```

API 로 확인하려면 위 JSON 을 그대로 `POST /evaluate` 에 보내면 된다 (`as_of` 포함).
