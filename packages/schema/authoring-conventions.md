# 정책 JSON 작성 컨벤션 (v1.2)

> 수동 정답지 batch-1 작성에서 확정된 세칙. CLAUDE.md의 절대 규칙과 파싱 규칙(#19)을 전제로 하며
> 중복 기술하지 않는다. 이 문서는 팀 계약서다 — 변경은 전원 리뷰.
> 스키마 필드 추가가 **기각**된 갭들의 운영 규칙을 포함한다 (§5).

## 1. 원문(정본) 규칙

- **회차 모집형 hs- 사업**: 정본은 모집 공고문(PDF). `source_url`은 공고문이 첨부된 잡아바어플라이
  상세 페이지. 시 안내 페이지는 요약본이라 조건이 누락된다 (실증: 공고 제2026-2594호의 지원 제외
  대상 섹션이 안내 페이지에 없음).
- **연중 제도형 hs- 사업**(공고 없이 조례로 운영): 정본은 시 안내 페이지. 그 URL을 `source_url`로.
- **kr- 사업**: 정본은 복지로 API 응답 텍스트(tgtrDtlCn·slctCritCn, 엔티티 해제본). 웹 화면 아님.
  servId를 PR "대조한 원문" 칸에 기록.
- 원문 사본은 `data/raw/`에 보관하고, PR "대조한 원문" 칸에 참조한 URL·파일을 전부 기입한다.
- 소스 관할: 시 페이지·공고에서는 hs-만, 복지로에서는 kr-만 뽑는다 (중복 유입 방지).
  경기도 광역 사업은 채번 불가로 범위 제외 (로드맵).

## 2. 조건 이원화 — 문장 단위 3갈래

원문의 자격요건 문장을 하나도 빠짐없이 분류한다 (검수 ⑦의 대상):

| 문장이… | 간다 |
|---|---|
| 숫자·보기선택이고 4키(age·income_percentile·residence_months·household)에 해당 | `conditions` (년→개월 환산) |
| 타 사업·타 제도 수혜로 인한 제외 (중복수급 제한, 타 급여로 동일 지원을 받는 경우 포함) | `exclusions` |
| 그 외 전부 — 서술형, 자격 배제(“~인 사람 제외”), **스키마에 자리 없는 숫자 조건** | `manual_conditions` |

- 판례: 보증금 3억(숫자지만 자리 없음)·무주택·전용면적 → manual / 장기요양등급 인정자 제외
  → exclusions (복지용구 급여로 동일 지원 수령 가능) / 기초수급자(생계·의료·주거) 제외 → exclusions
- `manual_conditions.label`은 **원문 문구 그대로**. 작성자 주석 금지 (주석은 PR 비고로).
- `verify_required`는 **conditions에 실제 존재하는 키만** 참조한다.

## 3. 필드별 세칙

- **기간이 명시되지 않은 "화성시 거주(주민등록)" 요건은 생략한다** — 프로필 자체가 화성시민 전제.
  manual에 넣으면 모든 hs- 정책이 '서류 확인' 이하로 갇힌다. 검수 ⑦에서 누락으로 치지 않는다.
- **household 제한이 없으면 `["제한없음"]`을 명시한다** (hs-2026-0263·2673 관행. 검수 ⑦에서
  "확인했고 제한 없음"과 "빠뜨림"을 구분해준다). 주의: 프로필 household_type에 이 값이 없으므로
  엔진은 `제한없음`을 항상-참으로 특례 처리해야 한다 (B의 evaluate 구현 TODO).
- **deadline**: 원문에 "연중·상시·소진 시"가 명시됐거나 기간 규정이 없는 연중 제도형일 때만 `null`,
  근거를 PR 비고에 남긴다. "원문에서 못 찾음"은 null이 아니다 — 회차 사업은 잡아바에서 확인한다.
- **title은 상시 사업명** — "2026년 하반기" 등 회차 표기는 제거 (회차는 deadline이 담당).
- **apply_channel**: 창구명은 고정 철자 "잡아바어플라이"·"복지로"를 포함해 표기 (프론트가 창구명→대표
  URL 매핑으로 신청 버튼을 만든다).
- **required_docs**: 원문에 목록이 있으면 반드시 옮긴다. `["공고 확인 필요"]`는 미표기일 때만.
- **selection**: 원문에 정원·배점·선발·고득점 순 등의 문구가 있으면 `"심사선발"`, 없으면 생략.

## 4. 제출 절차 요점

- 작성자는 `review` 블록을 넣지 않는다 (검수자 몫). 제출 전
  `python scripts/validate_policies.py --allow-unreviewed` 통과 확인.
- 채번·파일명(=policy_id)은 조장 확정 후 일괄 반영.

## 5. 스키마 필드 추가가 기각된 갭 → 운영 규칙

| 갭 | 운영 규칙 |
|---|---|
| 접수 시작 전 정책 표시 불가 | 접수 중이거나 상시인 정책만 적재한다 |
| deadline이 시각(18:00 마감)을 못 담음 | 날짜만 기록. 알려진 한계로 수용 |
| null의 이원성(상시 vs 다음 회차 대기) | 회차 대기 상태 정책은 적재 보류 |
| 수급자·차상위 등 자격 축 부재 | manual_conditions로. 빈도를 보고 v1.3 후보 |
| 소득 타지표(건보료·절대액) | CLAUDE.md 파싱 규칙 준수 (manual행) |
| 경기도 광역 prefix | 범위 제외, 로드맵 |
